# Связность: модель угроз РФ-2026 и автопилот

Этот документ — инженерное сердце проекта. Здесь описано, что именно ломает соединение
в российских сетях и что Zales с этим делает.

Все утверждения о поведении блокировок проверялись по открытым источникам и репозиториям
на **сентябрь 2026** и подлежат перепроверке: это движущаяся мишень.

---

## 1. Что делает ТСПУ

| Приём | Как выглядит | Что это значит для клиента |
| --- | --- | --- |
| **Заморозка сессии** | После 15–20 КБ в одной TCP-сессии пакеты просто перестают доходить. RST не приходит, сокет остаётся «живым» | Ошибки не будет. Будет тишина. Нужно **самим** засекать тишину и переустанавливать транспорт |
| **Анализ TLS-отпечатка** | Reality старых сборок опознаётся по поведению `NewSessionTicket` в TLS 1.3 | Устаревшее ядро — уязвимость, а не неудобство. Обновление ядра критично |
| **Фильтрация по SNI** | Блокируется по имени в открытом поле ClientHello | Фрагментация ClientHello, либо Reality, где настоящего SNI в открытом виде нет |
| **Подмена и порча DNS** | Ответ приходит, но неправильный | Свой DNS сквозь туннель, вход на заставу по IP, а не по имени |
| **Ограничение по портам и профилю** | Нестандартные порты душатся, UDP режется | 443/TCP как основной путь, QUIC-протоколы не закладываем в первую версию |
| **Замедление вместо блокировки** | Работает, но со скоростью 1990-х | Ловится измерением пропускной способности, а не проверкой «есть связь / нет связи» |

**Главный вывод для архитектуры.** Отказ в российской сети чаще всего выглядит не как
ошибка, а как *ничего не происходит*. Обычный клиент в этот момент показывает
«Подключено» и молчит. Zales обязан отличать живую тропу от замороженной.

## 2. Что мы можем изменить на клиенте

Из одного ключа выводится множество способов дойти до той же заставы. Список ниже —
это и есть **лестница стратегий**.

| # | Стратегия | Что меняется в конфигурации | Против чего | Цена |
| --- | --- | --- | --- | --- |
| `S0` | Как в ключе | Ничего | Базовый случай, чистая сеть | — |
| `S1` | Фрагментация ClientHello | `freedom.fragment`: `packets: "tlshello"`, `length: "10-20"`, `interval: "10-100"` | Фильтрация по SNI | +30–80 мс на рукопожатие |
| `S2` | Смена отпечатка uTLS | `tlsSettings.fingerprint`: `chrome` → `randomized` → `firefox` → `safari` | Опознание клиента по отпечатку TLS | нет |
| `S3` | XHTTP в режиме `packet-up` | `network: "xhttp"`, `xhttpSettings.mode: "packet-up"` | **Заморозка сессии** — данные едут отдельными HTTP-запросами, длинной TCP-сессии просто нет | Требует поддержки на заставе |
| `S4` | Другой порт | 443 → 8443 / 2053 / 2083 / 2087 / 2096 | Блок по порту, работа через CDN | Требует настройки заставы |
| `S5` | Вход по IP | Адрес заставы — IP, `serverName` остаётся прежним | Порча DNS | Ломается при смене IP заставы |
| `S6` | Мультиплексирование выключено | `mux.enabled: false`, `xudpConcurrency: 0` | **Заморозка сессии**: мультиплексор набивает 15–20 КБ в один сокет за секунды и упирается в лимит быстрее всего | Чуть больше сокетов |
| `S7` | Шумовые пакеты перед рукопожатием | `freedom.noises` | Эвристики на первых байтах соединения | +20–50 мс |
| `S8` | Стратегия адресов | `domainStrategy`: `UseIPv4` / `UseIPv6` / `AsIs` | Кривой IPv6 у оператора, сломанный dual-stack | нет |

**Важное следствие про `S6`.** Мультиплексирование, которое в обычных сетях улучшает
жизнь, в российских сетях её ухудшает: чем плотнее упакована одна TCP-сессия, тем
быстрее она упирается в порог заморозки. Поэтому в профиле «российская мобильная сеть»
мультиплексор по умолчанию выключен, а не включён.

Стратегии **комбинируются**: реальный кандидат — это не одна строка из таблицы, а набор
вроде `S1+S2+S6+S8(UseIPv4)`. Пространство перебора ограничивается заранее заданными
пресетами, чтобы гонка не превратилась в полный перебор.

## 3. Гонка

Мы не проверяем стратегии по очереди — это медленно и раздражает. Мы устраиваем гонку в
духе Happy Eyeballs (RFC 8305).

```
t=0 мс     запускается кандидат №1 (лучший по профилю сети)
t=250 мс   если №1 ещё не подтвердил проход — стартует №2
t=500 мс   стартует №3
…          максимум 4 одновременно
```

**Что считается победой.** Не установленное TCP-соединение и даже не успешное
рукопожатие, а **успешный ответ на пробный HTTP-запрос сквозь туннель**. Только это
доказывает, что тропа действительно проходима, а не выглядит проходимой.

Победитель забирает туннель, остальные аккуратно гасятся. Результат — победа и время
до победы, поражение и причина — записывается в профиль сети.

## 4. Профиль сети

Одна и та же стратегия ведёт себя по-разному в домашнем Wi-Fi и в мобильной сети
оператора. Zales это запоминает.

**Отпечаток сети** — стабильный ключ, по которому узнаётся «эта же сеть»:

- Wi-Fi: `SHA-256(SSID + первые три октета BSSID)`, усечённый до 8 байт
- Мобильная сеть: `MCC + MNC + тип подключения` (LTE / NR / …)
- Прочее: тип транспорта

Хранится только хэш — ни SSID, ни BSSID в открытом виде на диск не попадают.

**Что помнит профиль:**

```kotlin
data class NetworkProfile(
    val fingerprint: NetworkFingerprint,
    val ranking: List<StrategyScore>,   // отсортировано, лучшая первой
    val lastSuccessAt: Instant?,
    val consecutiveFailures: Int,
    val observedThrottling: Boolean,    // была ли замечена заморозка
)
```

Оценка стратегии — экспоненциальное скользящее среднее по успешности и времени до
победы, с затуханием по времени: то, что работало полгода назад, весит меньше того, что
работало вчера.

**Эффект для человека.** Первое подключение в новой сети может занять три-четыре
секунды. Второе и все последующие — меньше секунды, потому что правильная стратегия уже
стоит первой в очереди.

## 5. Сторож

Работает всё время, пока тропа открыта. Его задача — заметить, что тропа умерла, раньше,
чем это заметит человек.

**Пассивное наблюдение** (бесплатно, всегда):

- счётчики байт из `hev-socks5-tunnel`
- признак заморозки: приложение отправляет данные, туннель их принимает, но исходящий
  объём стоит на месте больше 6 секунд при непустой очереди
- падение пропускной способности больше чем в 8 раз от скользящего среднего

**Активная проба** (только при подозрении, не по расписанию):

- лёгкий HTTP-запрос сквозь туннель с бюджетом 3 секунды
- не прошла — вторая попытка через 2 секунды
- две подряд — состояние `Degraded`, тихий перезаход следующей стратегией из профиля

**Что видит человек.** Слово на экране меняется на «ТРОПА СУЗИЛАСЬ», лес чуть
подступает, внизу появляется «Ищу обход». Рубильник остаётся внизу — соединение не
рвалось, его чинят. Если обход нашёлся за это время, человек, скорее всего, вообще
ничего не заметил.

## 6. DNS

Утечка DNS — самая частая дыра в самодельных VPN-клиентах, поэтому здесь всё явно.

1. `VpnService.Builder.addDnsServer` указывает на **внутренний адрес** (`10.16.0.1`),
   который слушает сам Xray. Ни один запрос не уходит к DNS оператора.
2. Внутри Xray настроен DoH-резолвер, доступный **через туннель**.
3. Для доменов раздельной маршрутизации (см. ниже) используется отдельный резолвер,
   идущий напрямую, — иначе российские сайты будут отдавать зарубежные CDN-адреса и
   работать хуже, чем без VPN.
4. `blockDomains` для рекламно-трекерных зон — опционально, по умолчанию выключено.
5. В фазе 9 утечка проверяется отдельным пунктом аудита, на реальном устройстве.

## 7. Раздельная маршрутизация

По умолчанию **включена**: российские домены и IP-диапазоны идут напрямую, мимо тропы.

Почему это правильно по умолчанию:

- банки и госуслуги часто отказывают в обслуживании при заходе с зарубежного IP
- канал заставы не тратится на местный трафик
- меньше данных проходит через одну TCP-сессию — реже упираемся в заморозку

Источник списков — `geosite.dat` и `geoip.dat` от Xray, категории `geosite:category-ru`
и `geoip:ru`. Обновление — фоновой задачей раз в неделю, файл проверяется по хэшу.

Отключается одним переключателем: «Всё через тропу».

Отдельно — **список приложений мимо тропы**: банковские приложения нередко проверяют
наличие VPN. Человек выбирает их из списка с иконками, без ввода имён пакетов.

## 8. Чего клиент не может

Честная граница ответственности. Эти вещи чинятся только на стороне заставы, и Zales
должен уметь **сказать об этом прямо**, а не бесконечно перебирать стратегии:

| Проблема | Что нужно сделать на заставе |
| --- | --- |
| Reality опознан по TLS-отпечатку | Обновить Xray-core на сервере до свежего релиза |
| Плохой выбор `serverName` | Взять реально существующий и достижимый из РФ домен с TLS 1.3 и HTTP/2 |
| Не работают WhatsApp и Instagram | Добавить IPv6 на выходной узел |
| IP заставы попал в список | Сменить IP, лучше — поставить промежуточный узел |
| Нет XHTTP | Обновить конфигурацию сервера — без него недоступна лучшая защита от заморозки |

Эти диагнозы выводятся движком диагностики и показываются в разделе «для того, кто дал
ключ» — вместе с готовым текстом, который можно переслать одним нажатием.
