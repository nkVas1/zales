# Безопасность

---

## 1. От чего защищаемся

| Противник | Что может | Что делаем |
| --- | --- | --- |
| Пассивный наблюдатель в сети (провайдер, Wi-Fi кафе) | Видит метаданные, пытается опознать протокол | Reality / XTLS-Vision, фрагментация, смена отпечатков uTLS |
| Активный фильтр (ТСПУ) | Замораживает, замедляет, зондирует | Лестница стратегий, сторож, XHTTP `packet-up` — см. [CONNECTIVITY.md](CONNECTIVITY.md) |
| Человек с телефоном в руках | Открывает приложение, ищет ключ | Ключ в Android Keystore, биометрия на просмотр, `FLAG_SECURE` на экране ключа |
| Другое приложение на устройстве | Читает наши данные, снимает экран | Приватное хранилище, экспорт компонентов запрещён, `allowBackup=false` |
| Злонамеренная сборка приложения | Подменяет APK с тем же именем | Подпись релиза, публикация хэшей, воспроизводимая сборка |

**Вне модели угроз:** физический доступ с разблокированным загрузчиком, компрометация
самой заставы, целевая атака на конкретного человека. Zales — не инструмент для тех,
чья жизнь зависит от анонимности. Это инструмент, чтобы интернет работал.

## 2. Хранение ключа

1. Мастер-ключ генерируется в **Android Keystore**, `setUserAuthenticationRequired`
   для операции просмотра, `StrongBox` — если устройство его поддерживает. Ключ
   невыгружаем: приватный материал не покидает защищённый элемент.
2. Ключи доступа лежат в `EncryptedSharedPreferences` (AES-256-GCM) на мастер-ключе.
3. **Секрет не поднимается в слой интерфейса.** `KeyRepository` отдаёт наверх
   `KeyDescriptor` — имя, протокол, домен, дата добавления. Сам секрет разворачивается
   только в процессе `:tunnel` в момент сборки конфигурации.
4. Экран показа ключа: `FLAG_SECURE` (нет в списке недавних, нельзя снять скриншот),
   раскрытие по биометрии, автоскрытие через 30 секунд.
5. `android:allowBackup="false"` и пустые правила извлечения данных — ключ не уезжает
   в облачный бэкап Samsung или Google.
6. Удаление ключа стирает и запись, и связанный материал в Keystore.

## 3. Утечки трафика

| Канал утечки | Мера |
| --- | --- |
| DNS | Собственный резолвер внутри Xray, системные DNS не используются. Проверяется в аудите фазы 9 |
| IPv6 | Либо заворачивается в туннель полностью, либо блокируется. Полумер нет |
| Трафик до поднятия туннеля | `VpnService` поднимается до старта ядра; приложение не делает ни одного сетевого запроса на старте |
| Обрыв туннеля | Always-on VPN плюс системная блокировка соединений без VPN — приложение приводит пользователя к этой настройке пошагово |
| Локальная сеть | Диапазоны RFC 1918 исключаются из маршрутов — иначе перестанут работать принтер и телевизор |
| Обновления и телеметрия | Единственный необязательный сетевой запрос — проверка релиза на GitHub, выключается одним переключателем |

## 4. Целостность сборки

- Релизная подпись — ключ в GitHub Secrets, локально не хранится. `*.jks` и
  `keystore.properties` в `.gitignore` с первого коммита.
- CI публикует **SHA-256 каждого APK** в теле релиза.
- Цель — воспроизводимая сборка: фиксированные версии инструментов, фиксированное
  время сборки, детерминированный порядок ресурсов.
- Нативные артефакты собираются в CI из исходников по закреплённому тегу и проверяются
  по контрольной сумме при загрузке в Gradle. В репозитории нет ни одного бинарника.
- Зависимости фиксируются точными версиями в `libs.versions.toml`, lock-файлы Gradle
  коммитятся.

## 5. Чего приложение не делает

- Не имеет ни одного жёстко зашитого адреса сервера, кроме `api.github.com` для
  необязательной проверки обновлений.
- Не собирает и не отправляет аналитику. Ни одной. Никуда.
- Не запрашивает разрешений сверх необходимого: `INTERNET`, `FOREGROUND_SERVICE`,
  `FOREGROUND_SERVICE_SPECIAL_USE`, `POST_NOTIFICATIONS`, `RECEIVE_BOOT_COMPLETED`,
  `CAMERA` (только по факту открытия сканера QR).
- Не встраивает ни одного SDK третьих лиц: ни рекламы, ни отчётов о падениях, ни карт.
- Не показывает чужих серверов и не предлагает «бесплатные ключи».
