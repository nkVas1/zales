# Роадмап Zales

Десять фаз. Каждая заканчивается **работающей сборкой, которую можно поставить на
телефон** — никаких «фаза 1 = скелет без функций». Внутри фазы работа идёт атомарными
шагами: изменение → проверка → коммит.

Легенда статусов: ▢ не начато · ◐ в работе · ▣ готово

---

## Сквозные критерии качества

Действуют в каждой фазе, проверяются перед закрытием фазы:

| Ворота | Проверка |
| --- | --- |
| Сборка | `./gradlew assembleRelease` без warning'ов от Kotlin `-Werror` |
| Статика | `detekt` + `ktlint` + Android Lint — чисто |
| Тесты | Затронутые модули зелёные; для парсеров и стратегий — property-based |
| Прогон на устройстве | Реальный Samsung, а не только эмулятор |
| Утечки | `LeakCanary` в debug — ни одной утечки Activity/Service |
| Производительность | Нет кадров дольше 16 мс на главном экране (Macrobenchmark) |
| Безопасность | Ни одного секрета в git; сетевая активность только через туннель |
| Документация | Затронутые документы обновлены **в том же коммите** |

## Фаза 0 · Основание ▣

**Цель.** Пустая, но настоящая машина: репозиторий, инструменты, CI, скелет проекта,
зафиксированные решения.

**Работы**

1. ▣ Решения и ADR 0001–0006
2. ▣ Проектная документация: архитектура, дизайн, голос, связность, диагностика, безопасность
3. ▣ Репозиторий на GitHub, публичный, MPL-2.0
4. ▣ Инструменты: JDK 21 (Temurin 21.0.12), Android SDK (cmdline-tools 23.0, platform 37.0 и 37.2, build-tools 37.0.0, platform-tools 37.0.1), Gradle 9.7.1. Go, gomobile и NDK — по мере надобности в фазе 1
5. ▣ Gradle-скелет: version catalog, convention-плагины в `build-logic`, модули `app`, `core:common`, `core:design`. **AGP 9.4.0 + Kotlin 2.4.20 + Compose BOM 2026.09.00**, compileSdk 37, minSdk 26
6. ▣ GitHub Actions `build.yml`: проверка wrapper'а, detekt, lint, тесты, debug и release сборки, выгрузка APK. Плюс `dependabot.yml`
7. ▣ `SETUP.md` переписан по факту прогона на чистой машине, с ловушками AGP 9 и новой CLI Android SDK
8. ▣ Прогон на реальном устройстве — **Galaxy A12 (SM-A127F)**: Exynos 850, 3.8 ГБ RAM, 720×1600, 60 Гц, Android 13. Подключение по беспроводной отладке: кабель оказался только для зарядки

**Готово, когда.** `./gradlew installDebug` ставит на телефон приложение, которое
открывает один экран со словом «Zales» и версией сборки. CI зелёный на push в `main`.

*Итог:* `detekt`, `lint`, обе сборки и CI — зелёные; релизный APK после R8 — 708 КБ.
На телефоне приложение стартует без ошибок, палитра и шкала на месте, системный
масштаб шрифта 1.1 выдерживается.

*Находка на устройстве:* подписи цветом `breath` (2.7 : 1) и шильдик цветом `cold`
(1.7 : 1) нечитаемы. Введён текстовый токен `rime` с контрастом 7 : 1; `breath`, `cold`
и `rust` больше не используются для текста.

**Риск.** Установка NDK и gomobile на Windows — самое хрупкое место всего проекта.
*Смягчение:* нативные артефакты собирает CI на Linux; локально они не нужны для работы над интерфейсом.

## Фаза 1 · Тропа

**Цель.** Трафик реально идёт через вашу заставу. Уродливо, зато по-настоящему.

**Работы**

1. `native/` — сборочные скрипты: libXray → `zales-core.aar` (gomobile, arm64-v8a + armeabi-v7a). Больше ничего нативного: TUN — вход самого Xray ([ADR-0007](adr/0007-native-tun-inbound.md))
2. GitHub Actions `native.yml`: собирает артефакт, публикует в релиз с тегом версии ядра, Gradle тянет его оттуда
3. `tunnel:api` — `TunnelEngine`, `TunnelState`, `TunnelEvent`, модель ошибок
4. `tunnel:engine-xray` — мост к `Invoke(json)`, сборщик конфигурации Xray, разбор ответов
5. Передача дескриптора в ядро через `xray.tun.fd` — переменная выставляется со стороны Go, иначе inbound её не видит
6. `tunnel:vpnservice` — `ZalesVpnService`: настройка `Builder` (маршруты, MTU, DNS, IPv6, обход локальных сетей), foreground-уведомление, корректный жизненный цикл
7. Проверка гипотез: поддерживает ли Xray `prefix` из ключей Outline; работает ли XHTTP в режиме `packet-up`; поведение при смене сети

**Готово, когда.** С захардкоженным ключом на реальном Samsung: `ifconfig.me` показывает
IP заставы, DNS не течёт, туннель живёт 30 минут при выключенном экране, остановка не
оставляет висящих потоков.

**Риск.** Xray может не поддерживать `prefix` из Outline.
*Смягчение:* ADR-0003 описывает запасной путь — собрать Outline SDK **в тот же**
вызов gomobile, чтобы Go-рантайм остался один.

## Фаза 2 · Ключ

**Цель.** «Вставьте ключ» работает для всего, что человеку могли прислать.

**Работы**

1. `parsing:` — разборщики: `vless://` со всеми транспортами, `ss://` SIP002, `ss://` legacy-base64, `ss://` с шифрами 2022 (SIP022), `ssconf://` и `https://` динамические ключи Outline, подписка base64-списком, `vmess://` и `trojan://` как бонус
2. Нормализация в собственную модель `AccessKey`, независимую от синтаксиса ссылки
3. QR: камера (CameraX + ML Kit Barcode) **и** распознавание из картинки в галерее — человеку часто присылают скриншот
4. Буфер обмена: при открытии экрана мягкое предложение «похоже, вы скопировали ключ»
5. Хранилище: `EncryptedSharedPreferences` поверх ключа из Android Keystore, `StrongBox` где есть, биометрия на просмотр ключа
6. Ошибки разбора → человеческие фразы. Не «malformed URI», а «в ссылке потерялся кусок — так бывает, когда её скопировали не целиком»

**Готово, когда.** Шесть форматов ключей подключаются без единой ручной настройки.
Property-based тесты на разборщиках не находят падений на случайном мусоре.

## Фаза 3 · Чаща

**Цель.** Появляется лицо продукта — то, ради чего проект затевался.

**Работы**

1. `core:design` — два цветовых семейства (холодная чаща и тёплая сторожка), типографика (Golos Text, JetBrains Mono, Caveat, резной логотип), сетка, тайминги
1a. **Контраст как тест.** Юнит-тест прогоняет каждую пару «текстовый токен × фон» в обеих темах и падает ниже 7 : 1. `rust` текст не несёт вовсе (2.6 : 1): в состоянии отказа фраза остаётся цветом `bone`, а `rust` — только метка рядом
2. **Шейдер дизеринга Байера 8×8 на AGSL**: трёхслойное поле леса с параллаксом по гироскопу, конус света лампы с неровным мерцанием, анимируемый порог раскрытия. Запасной путь для API 26–32 — предрассчитанная текстура и `ColorMatrix`
3. **Рубильник** — физически смоделированный: масса, инерция, пружина, защёлка, искра на замыкании одним дизеренным кадром, тяжёлый гаптик через `VibrationEffect.Composition`. Следы износа: скол эмали, вытертая рукоять, рукописная бумажка
4. Главный экран: чаща → просека. Плотность дизеринга, глубина леса и радиус света привязаны к реальному состоянию туннеля
5. **Слой жути** — апериодическое дыхание чащи, редкий «взгляд» в глубине, смещение леса между сеансами. Со всеми ограничителями из DESIGN.md, раздел 6: гаснет в состоянии отказа и в режиме «Только рубильник»
6. Переходы между экранами: растворение по порогу дизеринга, ни одного `fadeIn`
7. Светлая тема «Туман»: холодная мгла снаружи, те же тёплые предметы внутри

**Готово, когда.** Главный экран держит **60 кадров на Galaxy A12** — Exynos 850 с
Mali-G52, это и есть планка, а не флагман на 120 Гц. Рубильник ощущается как предмет, а
не как кнопка. Снимки экрана уходят в `design-archive/`.

## Фаза 4 · Автопилот

**Цель.** Соединение, которое чинит себя само. Главная инженерная ценность проекта.

**Работы**

1. **Лестница стратегий** — из одного ключа выводится набор вариантов подключения: прямой, с фрагментацией TLS, со сменой отпечатка uTLS, XHTTP в режиме `packet-up`, альтернативный порт, обход по IP вместо домена. Подробности в [CONNECTIVITY.md](CONNECTIVITY.md)
2. **Гонка** в духе Happy Eyeballs: стратегии пробуются со сдвигом по времени, побеждает первая ответившая, остальные аккуратно гасятся
3. **Профиль сети** — успех и неуспех запоминаются по отпечатку сети (хэш SSID, оператор, тип подключения). В следующий раз в этой же сети правильная стратегия идёт первой
4. **Сторож** — активные пробы сквозь туннель, распознавание «заморозки» ТСПУ (трафик встал после 15–20 КБ) и тихий перезаход другой стратегией
5. Реакция на смену сети, Doze, режим полёта; экспоненциальный backoff с джиттером
6. Ограничения Samsung One UI — «спящие приложения» и оптимизация батареи: обнаружение и мягкое ведение пользователя в нужный экран настроек

**Готово, когда.** В стенде с искусственными отказами (блокировка порта, обрыв,
залипание, смена сети) туннель восстанавливается без участия человека, а на экране это
выглядит как «ищу другую тропу», а не как ошибка.

## Фаза 5 · Толмач

**Цель.** Если всё-таки сломалось — человек понимает, что случилось и что нажать.

**Работы**

1. Движок проб: DNS → TCP → TLS → рукопожатие прокси → HTTP сквозь туннель → пропускная способность
2. Таксономия отказов (см. [DIAGNOSTICS.md](DIAGNOSTICS.md)) → фраза плюс одно понятное действие
3. Экран «Проверка тропы»: шаги проверяются по очереди, видно, где споткнулись
4. Технический отчёт — сворачиваемый блок «для того, кто дал ключ», копируется одной кнопкой, секреты вычищены
5. Прямые диагнозы: просроченный ключ и мёртвая застава называются своими именами, а не «нет соединения»

**Готово, когда.** Каждая запись таксономии воспроизводится в тестовом стенде и даёт
ровно ту формулировку и то действие, которые задуманы. Ни одного кода ошибки на
верхнем уровне интерфейса.

## Фаза 6 · Автоматика

**Цель.** Приложение работает само, вмешиваться не нужно.

**Работы**

1. Плитка в шторке — включить и выключить, не открывая приложение
2. Виджет на рабочий стол — большой, читаемый, с состоянием
3. Always-on VPN и блокировка соединений без VPN: пошаговое ведение в системный экран с проверкой результата
4. Автозапуск после перезагрузки, восстановление состояния
5. **«Ключ по наследству»** — передача ключа на другой телефон QR-кодом с экрана. Внук настраивает у себя, дедушка сканирует. Ноль ввода текста
6. Проверка обновлений через GitHub Releases и поддержка [Obtainium](https://github.com/ImranR98/Obtainium) для автообновления
7. Раздельная маршрутизация: российские домены мимо туннеля — экономит канал и снимает капчи у банков; список обновляется из geosite

**Готово, когда.** После настройки телефон можно перезагрузить, и всё продолжает
работать без единого касания. Передача ключа QR-кодом занимает меньше пятнадцати секунд.

## Фаза 7 · Голос

**Цель.** Приложение звучит как живой человек, а не как системное сообщение.

**Работы**

1. Полный проход по микрокопирайту: каждая строка интерфейса переписана по [VOICE.md](VOICE.md)
2. **Подсистема «Приговорки»** — корпус коротких живых фраз, появляющихся мелким текстом в паузах: пока вставляют ключ, пока идёт подключение, пока туннель просто работает. Контекстный подбор, редкие пасхалки, защита от повтора, полное отключение в настройках и, главное, **строгий запрет шутить, когда человек в стрессе**
3. Озвучка состояний для TalkBack — отдельные, более буквальные формулировки
4. Локализация: русский исходный, английский второй; архитектура i18n закладывается сразу

**Готово, когда.** Прочитав любые три экрана подряд, невозможно сказать, что текст
писала машина. Приговорки ни разу не появились в момент ошибки.

## Фаза 8 · Дедушкин тест

**Цель.** Тот самый пользователь ставит приложение и пользуется без подсказок.

**Работы**

1. Доступность: TalkBack на каждом элементе, зоны нажатия не меньше 56 dp, контраст основного текста не ниже 7:1
2. Поддержка системного увеличения шрифта до 200% без обрезаний и наложений
3. Режим «Только рубильник» — всё лишнее спрятано, ключ защищён от случайного удаления
4. Уважение к системной настройке уменьшения движения
5. **Настоящее тестирование на настоящем дедушке.** Наблюдение без подсказок, фиксация каждой заминки, переделка того, обо что споткнулись
6. Экран «Что делать, если не работает» — три больших шага, написанных для человека в панике

**Готово, когда.** Человек, впервые видящий приложение, подключается с одной попытки и
без вопросов. Заминки из наблюдения устранены, а не задокументированы.

## Фаза 9 · Застава

**Цель.** Релиз, которому можно доверять.

**Работы**

1. Хардненинг: R8 в full mode, `network_security_config` без cleartext, запрет резервного копирования ключей, `FLAG_SECURE` на экране ключа
2. Аудит утечек: DNS, IPv6, трафик до поднятия туннеля
3. Воспроизводимая сборка и публикация хэшей APK в релизе
4. Подпись релиза ключом из GitHub Secrets, `release.yml` по тегу
5. Разделение APK по ABI плюс универсальный APK
6. `INSTALL.md` со снимками реальной установки на Samsung
7. `SECURITY.md`, политика раскрытия уязвимостей, `CHANGELOG.md`, экран «О программе» со списком лицензий зависимостей

**Готово, когда.** По тегу `v1.0.0` CI собирает подписанные APK, публикует релиз с
хэшами, и APK ставится на чистый телефон строго по инструкции.

## После релиза

- Метрики качества **только на устройстве**: приложение показывает статистику
  пользователю и никуда её не отправляет.
- Свежесть ядра — вопрос безопасности, а не гигиены: libXray жёстко связан с последним
  релизом Xray-core, а устаревшее ядро в 2026 году детектируется по TLS-отпечатку.
  Автоматический еженедельный PR по новому релизу Xray-core.
- Кандидаты второй версии: второй движок (sing-box → Hysteria2, TUIC, AnyTLS,
  AmneziaWG), несколько застав с автовыбором, сборки для Wear OS и Android TV.

## Реестр рисков

| Риск | Вероятность | Влияние | Что делаем |
| --- | --- | --- | --- |
| Xray не поддерживает Outline `prefix` | средняя | среднее | Outline SDK в тот же вызов gomobile (ADR-0003) |
| Сборка NDK и gomobile на Windows | высокая | среднее | Нативные артефакты собирает CI на Linux |
| Samsung усыпляет приложение | высокая | высокое | Обнаружение и ведение в настройки (фазы 4 и 6) |
| Смена методов блокировки в РФ | высокая | высокое | Лестница стратегий расширяется данными, а не кодом |
| AGSL недоступен ниже API 33 | известная | низкое | Запасной путь на текстуре порога (фаза 3) |
| Устаревание libXray и Xray-core | высокая | высокое | Автоматический еженедельный PR на обновление ядра |
