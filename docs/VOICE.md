# Голос Zales и подсистема «Приговорки»

Половина ощущения от приложения — это его текст. Здесь описано, как Zales говорит, и
как устроена система живых фраз, появляющихся в паузах.

---

## 1. Кто говорит

Голос Zales — **лесник**. Немолодой, спокойный, знает своё дело, лишнего не болтает.
Он не продаёт, не восторгается и не извиняется по десять раз. Если что-то пошло не так —
скажет прямо и тут же скажет, что делать. Может пошутить, но никогда — над человеком и
никогда — в неподходящий момент.

**Чего он не делает никогда:**

- Не говорит «Упс!», «Ой!», «Что-то пошло не так»
- Не ставит восклицательных знаков (кроме одного места: «Прошли!»)
- Не пишет «пожалуйста, попробуйте позже»
- Не употребляет слов «безопасность», «шифрование», «приватность» в интерфейсе —
  это то, что приложение делает, а не то, чем оно хвастается
- Не использует эмодзи. Ни одного

---

## 2. Словарь

Технический жаргон заменён обиходными словами. Это не украшательство: «сервер не отвечает»
для пожилого человека — пустой звук, «застава молчит» — понятная картинка.

| Было | Стало |
| --- | --- |
| Сервер, endpoint | Застава |
| Подключиться | Открыть тропу |
| Отключиться | Закрыть |
| Подключено / отключено | Открыто / закрыто |
| Ключ доступа, конфигурация | Ключ |
| Блокировка, DPI, цензура | Чаща |
| Переподключение | Ищу обход |
| Задержка, ping, RTT | Отклик |
| Протокол, транспорт, стратегия | Способ пройти |
| Трафик за сессию | Сколько прошло |
| Handshake failed | Застава не отвечает |
| Split tunneling | Что идёт мимо тропы |
| Always-on VPN | Держать тропу открытой всегда |

**Технические слова не исчезают совсем** — они живут в разделе «для того, кто дал ключ»,
где нужны настоящие названия, чтобы человек мог их переслать.

---

## 3. Правила формулировок

1. **Сначала что случилось, потом что делать.** «Застава не отвечает. Скорее всего,
   ключ выдали давно — попросите новый.»
2. **Одно действие на сообщение.** Не «проверьте интернет, ключ и настройки», а самое
   вероятное — одно.
3. **Короткое предложение.** Больше двадцати слов — переписать.
4. **Никакого условного наклонения.** Не «возможно, соединение могло быть прервано», а
   «связь оборвалась».
5. **Приложение отвечает за себя.** Не «вы ввели неверный ключ», а «я не смог прочитать
   этот ключ».

## 4. Подсистема «Приговорки»

Приговорка — короткая фраза мелким текстом в нижней части экрана. Появляется сама,
пока человек ждёт: вставляет ключ, смотрит на открывающуюся тропу, просто сидит с
включённым туннелем.

Задача — снять напряжение ожидания и сделать приложение живым. Название взято из
фольклора: приговорка — короткая присказка, которую говорят под руку во время работы.

### 4.1 Железные правила безопасности

Эти правила важнее любой шутки. Нарушение — баг уровня «блокирует релиз».

| Правило | Почему |
| --- | --- |
| **Никогда при отказе.** В состояниях `Failed`, на экране диагностики и в любом сообщении об ошибке приговорок нет вообще | Человек в стрессе не хочет шуток. Он хочет решения |
| **Никогда во время `Degraded`.** Там свои фразы — короткие и успокаивающие, не смешные | Шутка в момент сбоя читается как издёвка |
| **Никогда не выглядит как инструкция.** Отдельный слот, мельче основного текста, цветом `--fog` | Иначе дедушка примет шутку за указание и будет её выполнять |
| **Никогда не блокирует и не требует реакции** | Это фон, а не диалог |
| **Полностью отключается одним переключателем** в настройках | Не всем нужно |
| **Не читается TalkBack по умолчанию** (`invisibleToUser`) | Иначе экранный диктор будет зачитывать шутки поверх важного |
| **Не повторяется** в пределах последних 25 показов | Повтор убивает эффект мгновенно |

### 4.2 Контексты

Фраза подбирается под ситуацию. Контекст — обязательное поле каждой строки.

| Контекст | Когда | Тон |
| --- | --- | --- |
| `idle` | Тропа закрыта, человек смотрит на экран | Созерцательный, лесной |
| `key_input` | Открыт экран ввода ключа | Ободряющий, снимающий страх ошибки |
| `connecting` | Первые 8 секунд подключения | Деловой, с лёгким азартом |
| `connecting_long` | Дольше 8 секунд | Терпеливый — «я не завис» |
| `connected_fresh` | Первые 20 секунд после успеха | Довольный, короткий |
| `connected_long` | Туннель работает больше часа | Спокойный, «можете не проверять» |
| `reconnecting` | `Degraded` | **Только успокаивающие. Без шуток** |
| `first_run` | Самый первый запуск | Приветственный |
| `veteran` | Больше 100 успешных подключений | Свойский |
| `night` | 23:00–05:00 | Тихий |
| `morning` | 05:00–09:00 | Свежий |
| `rare` | Вероятность 1.5 % в любом контексте | Абсурд, пасхалки |

### 4.3 Как выбирается

```kotlin
fun pick(ctx: Context, history: RecentIds): Saying? {
    if (ctx.isStressful) return null                    // правило №1, до всякой логики
    val pool = corpus
        .filter { ctx.tag in it.contexts }
        .filter { it.id !in history.last(25) }
        .filter { it.conditions.all { c -> c.holds(ctx) } }
    val rare = corpus.filter { it.tier == RARE && it.id !in history.last(25) }
    return if (Random.nextFloat() < 0.015f && rare.isNotEmpty()) rare.random()
           else pool.weightedRandom()                   // вес 1..5, редкое реже
}
```

**Тайминг показа.** Появляется через 1.2 с после входа в состояние — чтобы не мелькать
при быстром переходе. Держится не меньше 4 с. Меняется не чаще чем раз в 9 с. Уходит
и приходит через растворение по дизерингу, как всё остальное в приложении.

### 4.4 Формат данных

Корпус — ресурс `core/voice/src/main/assets/sayings.json`, отделён от кода, чтобы
пополнять его без пересборки логики. Локализуется как обычный ресурс.

```json
{
  "id": "idle_moss",
  "text": "Мох растёт. Медленно, но растёт.",
  "contexts": ["idle"],
  "tier": "common",
  "weight": 3,
  "conditions": []
}
```

Тесты корпуса, зелёные обязательно: уникальность `id`, ни одной строки длиннее
64 символов, ни одного восклицательного знака вне белого списка, ни одного эмодзи,
покрытие каждого контекста минимум пятнадцатью строками.
