# ADR-0003. Один Go-рантайм, один AAR, сборка в CI

- **Статус:** принято
- **Дата:** 2026-09-10

## Контекст

Документация libXray формулирует жёсткое ограничение: **в одном процессе может жить
только один Go-рантайм.** Две независимо собранные Go-библиотеки объединить нельзя —
нужно собирать все Go-пакеты одним вызовом.

Это важно прямо сейчас: есть вероятность, что Xray не поддерживает `prefix` из ключей
Outline (обфускация первых байт соли Shadowsocks) и SS-over-WebSocket. Если так,
понадобится [Outline SDK](https://github.com/Jigsaw-Code/outline-sdk) (Apache-2.0) —
и подключить его отдельным AAR будет **невозможно**.

Отдельный вопрос: где собирать. Связка gomobile + NDK на Windows работает плохо, а
основная машина разработчика — Windows.

## Решение

1. Все Go-зависимости собираются **одним вызовом gomobile** в единый артефакт
   `zales-core.aar`. Сейчас там только libXray; при необходимости Outline SDK
   добавляется в тот же модуль Go, а не рядом.
2. Нативные артефакты (`zales-core.aar`, `libhev.so`) собирает **GitHub Actions на
   Linux** и публикует в GitHub Release с тегом версии ядра.
3. Gradle забирает их оттуда, **проверяя SHA-256**. В репозитории нет ни одного
   бинарного файла — `*.aar` и `*.so` в `.gitignore`.

## Почему

- Ограничение Go-рантайма — не рекомендация, а физика: обойти его нельзя, можно только
  учесть заранее. Учтённое сейчас, оно стоит ноль; обнаруженное в фазе 2 — стоит
  переделки сборки.
- Linux в CI избавляет от самой хрупкой части инструментария на машине разработчика.
  Работа над интерфейсом при этом не блокируется: артефакты уже готовы.
- Сборка из исходников по закреплённому тегу плюс проверка хэша — это цепочка поставок,
  которую можно проверить. Для VPN-клиента вендоринг чужого бинарника недопустим.

## Последствия

- Правка нативного кода требует прогона workflow, а не локальной сборки. Это медленнее
  на несколько минут и надёжнее на порядок.
- Обновление ядра — это обновление тега, пересборка артефакта и обновление хэша в
  version catalog. Процесс автоматизируется еженедельным PR.
- Локальная сборка нативных артефактов остаётся возможной и описана в
  [SETUP.md](../SETUP.md), но помечена как необязательная.
