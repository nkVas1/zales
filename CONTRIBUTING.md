# Участие в разработке

## Порядок работы

```
1. АНАЛИЗ        прочитать релевантный код целиком, а не по кускам
2. ПЛАН          атомарные шаги
3. РЕАЛИЗАЦИЯ    по одному шагу, с проверкой после каждого
4. ТЕСТЫ         там, где они действительно защищают от регрессии
5. ДОКУМЕНТАЦИЯ  обновить затронутые документы в том же коммите
6. РЕВЬЮ         перечитать diff целиком
7. КОММИТ        атомарный, с осмысленным сообщением
```

## Ворота качества

Перед каждым коммитом:

```bash
./gradlew lint detekt test
```

Перед каждым push в `main` — дополнительно прогон на реальном устройстве.

## Коммиты

[Conventional Commits](https://www.conventionalcommits.org/), тема на английском:

```
feat(tunnel): add strategy racing with happy-eyeballs delays
fix(parsing): accept ss:// links with percent-encoded userinfo
docs(design): specify Bayer threshold ranges
```

Тело — отдельным `-m`, если изменение требует объяснения. Никаких литеральных `\n`
внутри сообщения.

Что не коммитим никогда: сломанный код, артефакты сборки, ключи подписи, реальные
ключи доступа, бинарники.

## Ветки

- `main` — всегда собирается и работает
- `feat/<что>`, `fix/<что>`, `docs/<что>`

## Правила, специфичные для этого проекта

1. **`feature/*` не зависит от `tunnel:engine-*`.** Только от `tunnel:api`. Проверяется
   тестом на граф модулей.
2. **Ни одного `fadeIn`/`fadeOut`.** Переходы — растворение по порогу дизеринга
   ([DESIGN.md](docs/DESIGN.md), раздел 10).
3. **Ни одного кода ошибки в интерфейсе.** Отказ проходит через таксономию
   ([DIAGNOSTICS.md](docs/DIAGNOSTICS.md)) и превращается во фразу с одним действием.
4. **Ни одной приговорки в состоянии отказа.** Правило проверяется тестом
   ([VOICE.md](docs/VOICE.md), раздел 4.1).
5. **Минимальный размер текста — 16sp.** Исключение одно: технический шильдик 14sp
   моноширинным, и только для данных, не для инструкций.
6. **Секрет ключа не поднимается выше `KeyRepository`.** Наверх уходит дескриптор.
7. **Новая зависимость — только с открытой лицензией** и обоснованием в описании PR.
   Библиотека ради одной функции не добавляется. Лицензии, несовместимые с MPL-2.0
   в проприетарной надстройке (GPL, AGPL), — только с явного согласования.
8. **Заголовок лицензии в каждом новом исходном файле.** MPL-2.0 привязывает копилефт
   к файлу, поэтому шапка здесь не формальность:

   ```kotlin
   // This Source Code Form is subject to the terms of the Mozilla Public
   // License, v. 2.0. If a copy of the MPL was not distributed with this
   // file, You can obtain one at https://mozilla.org/MPL/2.0/.
   ```

## Дизайн

Сначала полностью проходим код экрана и правим всё найденное, и только потом смотрим
результат на устройстве. Важные снимки после структурных изменений — в
`design-archive/` с датой и номером фазы.
